## 한국어

- **관리형 Caddy 설치가 재시작 반복으로 실패하던 문제**: CA가 없는 mTLS 사이트처럼 Caddy가 아직 읽을 수 없는 사이트는 설치 때 처음 쓰는 Caddyfile에서도 보류합니다(설치 로그에 표시). 설치가 실패하면 컨테이너를 정리하기 전에 그 로그를 남기고 원인 줄을 오류 메시지에 붙입니다
- 설치 창 네트워크 칸: 아직 없는 네트워크 이름을 넣으면 「새로 만들고 길목도 연결합니다」로 안내
- 마법사 구성요소 단계: 실제로 미리 고른 것이 있을 때만 「미리 골라 두었습니다」 표시
- 관리형 스택 문구의 조사 정리(「CrowdSec를」 등)
- 개발: 기능 전체 통합 테스트 `dev/e2e/integration.py`, 이미지 빌드와 테스트를 나란히 돌려 배포 시간 단축

## English

- **Managed Caddy install failing with a crash-looping container**: sites Caddy cannot load yet (such as mTLS sites before the CA exists) are held in the first Caddyfile of an install too (shown in the install log). When an install fails, the container's log is kept before cleanup and its error line is added to the message
- Install dialog network field: a network that does not exist yet is announced as "created, and Gilmok joins it"
- Setup wizard components step: "pre-selected from the containers found" only when something was actually pre-selected
- Wording fixes in the managed-stack texts
- Development: full-feature integration test `dev/e2e/integration.py`; the image build runs alongside the tests for a faster release
