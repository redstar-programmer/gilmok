Docker 밖에서 실행하는 Caddy(관리 API 또는 같은 PC의 실행 파일)도 대시보드 요청 통계를 모을 수 있게 한 릴리스입니다. · Request statistics for Caddy running outside Docker (admin API or a local binary).

```bash
docker pull vitive/gilmok:0.1.15   # linux/amd64 · linux/arm64
```

**업데이트 · Upgrading:** `docker compose pull && docker compose up -d`

## 한국어

- Caddy 탭 › 연결에 「접근 로그 파일」 — Caddy 위치가 「PC에 설치」일 때 Caddy가 쓸 파일 경로(예: `C:/Caddy/logs/access.log`)를 적고 적용하면, 사이트마다 그 파일로 접근 로그를 남기고(50MB마다 교체·3개 보관) 길목이 따라 읽어 대시보드·지도·접속자·로그 탭을 Docker Caddy와 똑같이 채웁니다
  - 길목이 Docker 안이고 Caddy가 PC에 있으면 Caddy 로그 폴더를 길목 컨테이너에 마운트하고 「길목이 보는 위치」에 그 경로를 적으세요 (예: `C:/Caddy/logs:/stacks/caddy-logs:ro`)
  - 처음 연결할 때 최근 1시간을 읽어 적용 직후의 요청도 빠지지 않고, Caddy가 파일을 교체하면 새 파일을 처음부터 읽습니다. 파일은 읽을 때만 열어서 Windows에서도 Caddy의 교체를 막지 않습니다
- 로그 파일을 정하지 않았으면 대시보드에 「요청 통계 없음 — 접근 로그 파일을 정해야 합니다」와 바로가기
- Caddy 설정이 바뀌면 로그 수집이 5초 안에 따라옵니다 (예전엔 최대 30초)
- 남은 한계: Coraza WAF 차단 기록(Caddy 자체 로그)과 Caddy 재시작·업데이트는 Docker Caddy에서만

## English

- Caddy tab › Connection › "Access log file" — with Caddy installed on the PC, enter the file Caddy should write (e.g. `C:/Caddy/logs/access.log`) and apply: every site logs to that file (rolled every 50 MB, 3 kept) and Gilmok follows it to fill the dashboard, map, client details and Logs tab just like with Docker Caddy
  - With Gilmok in Docker and Caddy on the PC, mount the Caddy log folder into the Gilmok container and enter that path under "where Gilmok sees it" (e.g. `C:/Caddy/logs:/stacks/caddy-logs:ro`)
  - The first connect reads the last hour, so requests right after the apply are not lost; when Caddy rolls the file the new one is read from the start. The file is only opened while reading, so Caddy can roll it on Windows too
- Without a log file the dashboard says so and links to the setting
- Log collection follows a Caddy setting change within 5 seconds (was up to 30)
- Still Docker-only: Coraza WAF block records (Caddy's own log) and restarting / updating Caddy
