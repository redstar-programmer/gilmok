## 한국어

- 요청이 한꺼번에 많이 들어올 때(로그 스트림 재연결, 로그 파일 첫 읽기) 로그 DB가 2만 건 넘는 몫을 버리던 문제 — 이제 잠깐 기다렸다 기록 (5만 건 0.23초, 버림 0)
- 대시보드 긴 기간 조회가 빨라짐: 필터를 건 패널들이 같은 데이터를 한 번만 읽고, 지도 집계는 한 번 훑기로 (요청 20만 건 · 7일: 필터 9.5초 → 1.1초, 필터 없음 4.3초 → 2.3초)
- 한 요청이 서버를 오래 붙잡지 못하게: 대시보드 데이터 요청은 패널 40개, 필터 값은 사이트 200 · 국가 300개까지
- 로그인 전 쓰기 요청(로그인 · 언어 선택 · 첫 설정 · 로그아웃)에도 화면 전용 헤더(X-GM)를 요구 — 다른 사이트에서 보낸 요청 차단을 한 겹 더
- 테스트: `scn_perfsec_test.go` (PERF-01~06, SECD-01~06), 결과는 docs/TEST_SCENARIOS.md 「PERF · SECD」

## English

- A burst of requests (a log stream reconnecting, the first read of a log file) no longer loses everything past 20k in the log database — it waits briefly and records them (50k in 0.23 s, none dropped)
- Faster long dashboard ranges: filtered panels read the rows once per refresh, and the map adds everything up in one pass (200k requests over 7 days: filtered 9.5 s → 1.1 s, unfiltered 4.3 s → 2.3 s)
- One request can no longer keep the server busy for long: dashboard data requests take at most 40 panels, filters at most 200 sites and 300 countries
- The pre-login writes (login, language choice, first setup, logout) now also require the UI's X-GM header — one more layer against cross-site requests
- Tests: `scn_perfsec_test.go` (PERF-01..06, SECD-01..06); results in docs/TEST_SCENARIOS.md, "PERF · SECD"
