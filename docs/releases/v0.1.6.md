## 한국어

**적용이 통째로 막히지 않게**
- 사이트 하나 때문에 Caddy가 설정 전체를 거부하던 경우(기본 골격에 없는 스니펫, 길목이 설치한 Caddy에 mTLS CA 없음) — 그 사이트만 보류하고 나머지는 적용합니다. 보류한 사이트는 「적용 대기」와 미리보기에 이유와 함께 남습니다. mTLS 사이트는 검사 없이 열리지 않습니다
- Caddy 점검의 「mTLS CA」는 보류 중이면 「주의」로 표시합니다

**길목이 설치한 Caddy의 기본 골격 맞춤**
- 예전 Caddy에서 가져온 골격을 설치·가져오기·시작 때 이 Caddy에 맞춥니다: mTLS CA 경로, Authelia 주소, Cloudflare DNS 인증서(`acme_dns`), 빠진 `cf_only`·`authelia` 스니펫

**그 밖에**
- 마법사를 쓰지 않고 탭에서 설정해 적용하면 설정 완료로 기록합니다(로그인 때마다 설정 제안이 뜨지 않음)
- 적용 직전에 mTLS CA가 없을 때 알아보기 쉬운 안내

## English

**One site no longer blocks the whole apply**
- When a single site would make Caddy refuse the entire configuration (a snippet missing from the base configuration, or an mTLS site on a Caddy Gilmok installed without its CA), only that site is held and everything else is applied. Held sites stay in the pending list and the preview with the reason. mTLS sites are never served without the check
- The Caddy check shows "mTLS CA" as a warning while sites are held

**Fitting the base configuration of a Caddy Gilmok installed**
- A base imported from another Caddy is fitted on install, import and startup: mTLS CA path, Authelia address, Cloudflare DNS certificates (`acme_dns`), missing `cf_only` / `authelia` snippets

**Also**
- Setting up through the tabs and applying marks the setup as done (no setup prompt at every login)
- A clear message when the mTLS CA is missing right before applying
