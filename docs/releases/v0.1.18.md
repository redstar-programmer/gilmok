길목이 만드는 모든 사이트에 응답 압축(zstd·gzip)을 넣은 릴리스입니다 — 밖에서 접속할 때 페이지·API 응답이 빨라집니다. · Response compression (zstd, gzip) on every site Gilmok generates — pages and API responses load faster from outside.

```bash
docker pull vitive/gilmok:0.1.18   # linux/amd64 · linux/arm64
```

**업데이트 · Upgrading:** `docker compose pull && docker compose up -d` — 그다음 길목에서 「미리보기/적용」 (모든 사이트에 압축 줄이 추가됩니다) · then "Preview / apply" in Gilmok (every site gets the compression line)

## 한국어

- 모든 사이트에 `encode zstd gzip` 기본 적용. HTML·CSS·JS·JSON 같은 텍스트만 압축하고, 이미지·동영상·서비스가 이미 압축한 응답·아주 작은 응답은 그대로 둡니다. 집 업로드 속도가 병목인 원격 접속(휴대폰 데이터 등)에서 효과가 큽니다
- 서비스 편집 › 고급 설정 › 「응답 압축 (zstd·gzip)」으로 서비스마다 끌 수 있습니다. 추가 지시어에 직접 `encode`를 적은 서비스는 그 설정을 따릅니다
- 실제 시험: HTML·JSON이 zstd/gzip으로 줄고, PNG·이미 gzip인 응답·작은 응답은 그대로, SSE 실시간 이벤트도 압축된 채로 지연 없이 도착
- 대시보드 「전송량」은 실제로 보낸(압축된) 바이트라 적용 뒤 줄어 보입니다

## English

- `encode zstd gzip` on every site by default. Only text (HTML, CSS, JS, JSON, …) is compressed; images, video, responses the service already compressed and tiny responses are left alone. Biggest gain for remote access where the home upload speed is the bottleneck (mobile data etc.)
- Turn it off per service in the service editor › Advanced › "Response compression (zstd, gzip)". A service whose extra directives already contain `encode` keeps its own
- Real test: HTML and JSON shrink with zstd / gzip; PNG, already-gzipped and tiny responses pass through; SSE live events arrive on time while compressed
- The dashboard's "bytes sent" is what actually went out (compressed), so it drops after the apply
