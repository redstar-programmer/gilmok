처음부터 길목으로 설치할 때 막히던 인증서·네트워크 문제를 고친 릴리스입니다. · Fixes for certificates and networks when setting everything up with Gilmok from scratch.

```bash
docker pull vitive/gilmok:0.1.4   # linux/amd64 · linux/arm64
```

**업데이트 · Upgrading:** `docker compose pull && docker compose up -d` — 업데이트 뒤 「적용 대기」가 생기면 「적용」을 누르세요.

## 한국어

**인증서 (Cloudflare Proxied 사이트가 525가 되던 문제)**
- 설정 마법사에서 Cloudflare 단계를 Caddy 단계 앞으로 옮겼습니다. 길목이 설치하는 Caddy가 처음부터 Cloudflare DNS로 인증서를 받습니다
- 토큰 없이 설치된 관리형 Caddy는 토큰이 생기거나 길목이 다시 시작될 때 기본 골격에 `acme_dns`가 자동으로 들어갑니다(적용 대기)
- Caddy 점검에 「인증서 발급 방식」 — Proxied 사이트가 있는데 DNS 인증이 없으면 알려 줍니다

**네트워크 (Authelia가 502가 되던 문제)**
- Authelia·CrowdSec을 설치할 때 네트워크를 비워 두면 Caddy가 있는 네트워크에 설치합니다
- 설치 화면의 네트워크 칸에 추천(Caddy는 컨테이너가 가장 많은 네트워크, 나머지는 Caddy의 네트워크)과, Caddy와 갈라지는 선택에 대한 경고
- Authelia 점검에 「Caddy ↔ Authelia 네트워크」

**그 밖에**
- Caddyfile 경로 칸의 「Caddyfile 가져오기…」 — 이 서버에서 찾기 / 내 PC에서 고르기

## English

**Certificates (Cloudflare Proxied sites returning 525)**
- The setup wizard asks for Cloudflare before Caddy, so a Caddy installed by Gilmok gets its certificates through Cloudflare DNS from the start
- A managed Caddy installed without a token gets `acme_dns` added to its base configuration once a token exists or Gilmok restarts (pending apply)
- Caddy check "Certificate method" — warns when Proxied sites have no DNS challenge

**Networks (Authelia returning 502)**
- Authelia and CrowdSec are installed on Caddy's network when the network field is left empty
- The network field recommends a network (for Caddy: the one with the most containers; for the others: Caddy's) and warns when a choice would split them from Caddy
- Authelia check "Caddy ↔ Authelia network"

**Also**
- "Import Caddyfile…" next to the Caddyfile path — find it on this server or choose one on your PC
