## 한국어

- **`vitive/gilmok-caddy`** (linux/amd64·arm64): Caddy + Cloudflare DNS + Coraza WAF(OWASP CRS) + GeoIP. GitHub Actions가 매일 Caddy 새 버전을 확인해 올리고, 일요일마다 같은 버전도 다시 빌드해 바탕 OS 보안 수정을 반영합니다. 태그 `2.11.9`·`2.11`·`latest`
  - 길목이 새로 설치하는 Caddy는 이 이미지를 받습니다 — 빌드 몇 분이 없어지고, **Dockhand·Watchtower·Diun 같은 도구도 업데이트를 확인할 수 있습니다** (예전엔 직접 빌드한 이미지라 「Could not query registry」)
  - 이미 길목이 설치한 Caddy: compose.yml을 직접 고치지 않았으면, 길목이 시작할 때 이미지가 Docker Hub에 있는 것을 확인한 뒤 이 이미지를 쓰도록 바꿉니다. 실행 중인 컨테이너는 그대로이고 다음 이미지 업데이트 때 받습니다
  - 모듈을 더 넣으려면 설치 옵션 「이미지를 직접 빌드 (고급)」
  - 직접 운영하는 Caddy도 compose의 이미지를 `vitive/gilmok-caddy:latest`로 바꾸면 같은 모듈을 쓸 수 있습니다
- **자동 업데이트**: 「이미지 업데이트」 창(상단 「↑ 업데이트」)과 Caddy·Authelia 탭 › 이미지 업데이트에서 구성요소(Caddy·Authelia·CrowdSec)별로 켜고 매일 실행 시각을 고릅니다. 결과는 창과 로그 탭 › 시스템에
- **실패 시 되돌리기** (버튼·자동 모두): 업데이트 전에 지금 이미지를 `<이미지>:gilmok-prev`로 남겨 두고, 새 컨테이너가 정상 시작하지 못하면(Caddy는 지금 Caddyfile 검증까지) 그 이미지로 다시 만듭니다. 시험 중 Docker Desktop(containerd)이 이름 없는 이전 이미지를 바로 지우는 것을 발견해 백업 이름을 붙이게 했습니다
- CrowdSec도 「이미지 업데이트」 창에서 바로 업데이트됩니다 (LAPI 응답 확인)

## English

- **`vitive/gilmok-caddy`** (linux/amd64, arm64): Caddy + Cloudflare DNS + Coraza WAF (OWASP CRS) + GeoIP. GitHub Actions checks for new Caddy releases daily and rebuilds the current one every Sunday for base-OS fixes. Tags `2.11.9`, `2.11`, `latest`
  - A Caddy Gilmok installs now pulls this image — no build minutes, and **tools such as Dockhand, Watchtower and Diun can see its updates** (the locally built image used to give "Could not query registry")
  - A Caddy Gilmok installed earlier: unless its compose.yml was edited, Gilmok switches it to this image on start once the image is on Docker Hub. The running container stays; the next image update pulls it
  - Need more modules? Install option "Build the image locally (advanced)"
  - Your own Caddy can use the same modules by setting its compose image to `vitive/gilmok-caddy:latest`
- **Automatic updates**: in the "Image updates" dialog (top "↑ update") and Caddy / Authelia tab › Image update — switch on per component (Caddy, Authelia, CrowdSec) and pick the daily hour. Results in the dialog and Logs tab › System
- **Rollback on failure** (button and automatic): the running image is kept as `<image>:gilmok-prev` first; if the new container does not start properly (for Caddy: the current Caddyfile must validate too) it is recreated from that image. Testing showed Docker Desktop (containerd) deleting the untagged previous image at once, hence the backup name
- CrowdSec can now be updated right from the "Image updates" dialog (LAPI checked afterwards)
