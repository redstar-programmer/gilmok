다른 리버스 프록시에서 서비스 불러오기, 구성도의 Docker 네트워크 묶기, 로컬에서 바로 열기. · Import from other reverse proxies, topology grouped by Docker network, open locally.

```bash
docker pull vitive/gilmok:0.1.3   # linux/amd64 · linux/arm64
```

**업데이트 · Upgrading:** `docker compose pull && docker compose up -d`

## 한국어

**다른 프록시에서 불러오기** (서비스 탭 · Caddy › 리버스 프록시)
- 다른 Caddy의 Caddyfile, nginx(upstream 블록, Nginx Proxy Manager 호스트 파일), Traefik(동적 설정 YAML·TOML, docker-compose 라벨, 실행 중인 컨테이너 라벨)에서 사이트를 읽어 옵니다
- 미리보기에서 고른 것만 추가합니다. 지금 목록은 대체하지 않고, 이미 있는 서브도메인은 「대상 바꾸기」를 고른 것만 바꿉니다
- 다른 도메인의 사이트는 첫 이름을 서브도메인으로, 원래 인증이 걸려 있던 사이트는 알려 줍니다

**구성도**
- 「묶기: 공개 방식 | Docker 네트워크」 — 대상 컨테이너가 붙어 있는 네트워크별로 묶고, Caddy가 없는 네트워크는 경고색으로 표시합니다

**서비스 목록**
- 이름 옆 「↗」(사이트 열기)와 「:포트」(대상 컨테이너가 호스트에 게시한 포트로 바로 열기 — 서버 자신에서 접속했을 때)

**점검**
- CrowdSec: Cloudflare 동기화 문제는 「주의」(판정은 계속 동작), mTLS 사이트·요청이 아직 없는 것은 「참고」로 표시합니다

## English

**Import from another proxy** (Services tab · Caddy › Reverse proxy)
- Reads sites from another Caddy's Caddyfile, nginx (upstream blocks, Nginx Proxy Manager host files) and Traefik (dynamic config YAML / TOML, docker-compose labels, labels of running containers)
- Only the sites you pick in the preview are added. The current list is kept; existing subdomains change only when "Replace target" is ticked
- Sites on another domain use their first label as the subdomain; sites that had authentication are pointed out

**Topology**
- "Group: Exposure | Docker network" — groups services by the network their target container is on; networks Caddy is not on are shown in a warning color

**Service list**
- "↗" (open the site) and ":port" (open the target container's host-published port directly — when you are on the server itself)

**Checks**
- CrowdSec: Cloudflare sync problems are warnings (decisions keep working); no mTLS sites or no requests yet are shown as notes
