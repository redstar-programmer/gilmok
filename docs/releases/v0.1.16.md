Docker 밖에 설치한 Authelia와 CrowdSec도 길목으로 관리할 수 있게 한 릴리스입니다. · Authelia and CrowdSec installed outside Docker can now be managed too.

```bash
docker pull vitive/gilmok:0.1.16   # linux/amd64 · linux/arm64
```

**업데이트 · Upgrading:** `docker compose pull && docker compose up -d`

## 한국어

- **Authelia 위치** (Authelia 탭 › 연결): 「Docker 컨테이너」 / 「Docker 밖 (PC·다른 서버)」. 예전에는 Docker 밖 Authelia에 접근 정책·사용자를 적용하면 실패했습니다
  - Docker 밖이면 길목은 파일만 고칩니다 — 검증은 YAML 문법과 access_control 구조(길목에 Authelia 실행 파일이 없어서), 적용 후 상단에 「⟳ Authelia 재시작 필요」
  - Authelia를 직접 다시 시작하고 「다시 시작했어요」를 누르면 Authelia 주소의 `/api/health`로 정상인지 확인합니다. 시작하지 못하면 「이전 설정으로 되돌리기」
  - 사용자 변경: `authentication_backend.file.watch: true`면 보통 바로 반영되지만, 공유 폴더(Docker Desktop의 Windows 폴더·SMB·NFS)에서는 감지되지 않을 수 있어 알림을 남깁니다 (시험 중 실제로 확인)
  - 보안 이벤트(로그인 실패 등)는 Authelia 로그 파일(`log.file_path`)을 정하면 그 파일에서 모읍니다
- **CrowdSec 위치** (CrowdSec 탭 › 연결): Docker 밖이면 LAPI로만 연결합니다
  - 바운서 키는 그곳에서 `cscli bouncers add gilmok`으로 만들어 붙여 넣기 (저장 전에 LAPI로 확인)
  - 화면에서 IP 차단·해제는 머신 계정으로 (`cscli machines add gilmok --password <비밀번호> -f /dev/null` — `-f /dev/null`은 CrowdSec 자신의 접속 정보 파일을 덮어쓰지 않게). 비밀번호는 길목 데이터 폴더의 비밀 파일에만 저장
- Docker 밖 구성요소는 컨테이너 상태·이미지 업데이트·컨테이너 리소스 위젯에서 빠집니다 (길목이 다시 시작·업데이트하지 않음)

## English

- **Where Authelia runs** (Authelia tab › Connection): "Docker container" / "Outside Docker (PC, another server)". Applying policies or users to an Authelia outside Docker used to fail
  - Outside Docker Gilmok only edits the files — checks YAML syntax and the access_control structure (there is no Authelia binary to run), then shows "⟳ Authelia restart needed" at the top
  - Restart Authelia yourself and click "I restarted it": Gilmok checks `/api/health` at Authelia's address; if it did not start, "Put the previous settings back"
  - User changes: with `authentication_backend.file.watch: true` they usually apply at once, but shared folders (Docker Desktop's Windows folders, SMB, NFS) may not report the change, so a notice stays (seen in testing)
  - Security events (failed logins etc.) come from Authelia's log file (`log.file_path`) when set
- **Where CrowdSec runs** (CrowdSec tab › Connection): outside Docker Gilmok uses the LAPI only
  - Paste a bouncer key made there with `cscli bouncers add gilmok` (checked against the LAPI before saving)
  - Banning and unbanning IPs from the screen uses a machine account (`cscli machines add gilmok --password <password> -f /dev/null` — `-f /dev/null` keeps CrowdSec's own credentials file untouched); the password is kept only in a secret file in Gilmok's data folder
- Components outside Docker are left out of container status, image updates and the container resources widget (Gilmok does not restart or update them)
