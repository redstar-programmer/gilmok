재시작 직후 대시보드의 응답시간 분포·순위가 비어 보이던 문제와, 0.1.24에서 생긴 설정 저장 권한 문제를 고친 릴리스입니다. · Fixes request-level dashboard panels right after a restart, and a settings permission regression from 0.1.24.

```bash
docker pull vitive/gilmok:0.1.26   # linux/amd64 · linux/arm64
```

**업데이트 · Upgrading:** `docker compose pull && docker compose up -d`

## 한국어

- **재시작 직후 대시보드**: 응답시간 분포·많이 쓰는 사이트·접속 지역이 재시작 뒤 들어온 요청만 보여 줘, 요청 추이(재시작 전 기록 포함)와 맞지 않던 문제. 메모리의 최근 요청 목록이 보려는 기간을 다 덮지 못하면 요청 로그 DB에서 그립니다
- **설정 저장 권한 (0.1.24 회귀)**: 예전 데이터의 「신뢰 기기 유지 기간」(0)을 30으로 바꾸면서 보안 설정 변경으로 보여, 「계정·접근 보안」 권한이 없는 계정의 설정 저장·복원이 거부될 수 있던 문제. 0은 그대로 「기본 30일」로 둡니다. 설정 화면의 기간 목록도 「30일 (기본)」로 표시

## English

- **Dashboard right after a restart**: the response-time scatter, top sites and the map showed only requests since the restart, disagreeing with the request trend (which keeps its history). When the in-memory request list does not cover the range, those panels now read the log database
- **Saving settings (0.1.24 regression)**: older data's trusted-device period (0) was turned into 30, which looked like a security setting change and could refuse settings saves / restores for accounts without the account-security permission. 0 now stays as "default, 30 days", and the settings list shows "30 days (default)"
