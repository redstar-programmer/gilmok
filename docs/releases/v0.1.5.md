## 한국어

**mTLS (Cloudflare 인증된 원본 풀)**
- 길목이 설치한 Caddy의 「mTLS CA…」 → 「길목이 새로 만들기」: CA와 클라이언트 인증서를 만들어 클라이언트 인증서는 Cloudflare(존 단위 인증된 원본 풀)에 올리고 켜고, CA는 Caddy에 넣습니다. 개인 키는 길목에 남지 않습니다. 토큰 권한 `Zone · SSL and Certificates · Edit` 필요
- 이미 쓰는 CA는 파일로 고르거나 붙여넣어 넣을 수 있습니다
- Caddy 점검에 「mTLS CA」 — mTLS 사이트가 있는데 CA 파일이 없으면 알려 줍니다

**설정 마법사 · 빠른 설정**
- 마지막에 「마치고 적용…」 / 「적용…」 — 미리보기 후 바로 적용

**가져오기**
- 길목이 설치한 Caddy에 예전 Caddyfile을 가져오면 기본 골격(인증서 방식·CA 경로·Authelia 스니펫)은 지금 것을 유지하고 사이트만 가져옵니다. 예전 Authelia를 가리키던 사이트는 길목이 설치한 Authelia로 바꾸고, 로그인 포털 사이트는 남깁니다

## English

**mTLS (Cloudflare Authenticated Origin Pulls)**
- "mTLS CA…" on a Caddy installed by Gilmok → "Let Gilmok create it": a CA and a client certificate are created; the client certificate goes to Cloudflare (zone-level Authenticated Origin Pulls, switched on) and the CA into Caddy. No private key stays with Gilmok. Needs the token permission `Zone · SSL and Certificates · Edit`
- A CA you already use can be added from a file or pasted
- Caddy check "mTLS CA" — tells you when mTLS sites exist but the CA file is missing

**Setup wizard · quick setup**
- Ends with "Finish and apply…" / "Apply…" — preview, then apply right away

**Import**
- Importing an old Caddyfile into a Caddy installed by Gilmok keeps the current base configuration (certificate method, CA path, Authelia snippet) and imports only the sites. Sites pointing at the old Authelia are pointed at the one Gilmok installed, and the login portal site is kept
