업데이트 뒤 모든 서비스가 「응답 없음」으로 보이던 문제를 고치고, 대시보드에 상태코드 필터와 요청 상세를 더한 릴리스입니다. · Fixes every service showing "no response" after an update; adds a status filter and request details to the dashboard.

```bash
docker pull vitive/gilmok:0.1.10   # linux/amd64 · linux/arm64
```

**업데이트 · Upgrading:** `docker compose pull && docker compose up -d`

## 한국어

- **업데이트 뒤 모든 서비스가 「응답 없음」**: 길목이 Caddy·Authelia·CrowdSec을 설치할 때 길목 컨테이너를 그 네트워크에 붙이는데, 이 연결은 길목의 compose 파일에 없어 업데이트(컨테이너 재생성) 때 빠졌습니다. 그래서 길목만 서비스·CrowdSec에 닿지 못했습니다(사이트는 정상). 이제 시작할 때 관리형 구성요소의 네트워크에 다시 연결하고 시스템 이벤트로 남깁니다
- **대시보드 상태코드 필터**: 「응답시간 분포」·「상태코드별 추이」의 범례(2xx·3xx·4xx·5xx)를 눌러 숨기기·보이기(두 차트 함께, 브라우저에 기억). 드래그로 고른 요청 목록도 보이는 상태만
- **응답시간 분포 상세**: 점 위에서만 그 요청의 응답시간·상태·시각·사이트·요청(메서드·경로)을 표시(빈 곳은 표시 안 함), 점을 누르면 그 요청의 상세 창
- 서비스 상태 위젯: 막대의 의미(확인 한 번 = 막대 하나, 왼쪽이 오래된 것, 색 의미)를 한 줄로 안내하고 막대마다 시각·결과 툴팁

## English

- **Every service "not responding" after an update**: installing Caddy / Authelia / CrowdSec joins the Gilmok container to their network, but that join is not in Gilmok's compose file, so an update (the container is recreated) dropped it — Gilmok alone could not reach the services or CrowdSec (the sites kept working). Gilmok now rejoins its managed components' networks on start and logs a system event
- **Dashboard status filter**: click the legend (2xx · 3xx · 4xx · 5xx) of "Response time distribution" and "Requests by status" to hide or show a class (both charts, remembered per browser); the request list of a drag selection follows it
- **Response-time dots**: details only over a dot — response time, status, time, site, request (method and path); nothing over empty space. Clicking a dot opens that request
- Service status widget: one line explaining the bars (one check per bar, oldest on the left, colors) and a time / result tooltip on each bar
